# 第4步：100Hz异步融合与迟到观测回放

本步做了什么：把雷达点云和相机检测框接入同一个事件时间跟踪器，实现周期预测、不同采样率、缺测和迟到数据回滚。对应论文IV-D及图3。

- 输入分别携带采集时间、到达时间和唯一ID；同一传感器每个采集时间只能有一帧或一个已经选定的目标检测框。
- 100Hz预测时钟使用绝对时间网格。相同采集时间按雷达、相机、预测tick顺序处理，不在同一时刻重复预测。
- 保存原始点云/框、时间、更新后状态和协方差。迟到观测插入历史后，恢复此前快照，重新预测、门控、关联、计算相机观测，再回到当前预测时刻。
- 保留每一个100Hz tick。现有离散随机加速度Q不满足任意时间分割的半群性质，只重放观测、漏掉tick会改变协方差。
- 历史采用动态完整列表，便于检查。没有实现固定滞后窗口裁剪；长日志会占更多内存，不能据此声称Coral实时性能。
- 初始化一旦确定便冻结anchor；初始化前的迟到观测被忽略。回放与采集顺序等价的保证从相同anchor开始，不能保证完全不同初始化历史也等价。

两种相机模式：默认`paper_xyz`复现论文几何，但深度来自当前状态，与状态相关。`bearing`是另行标记的针孔EKF扩展，避免独立深度伪观测。默认R、Q、gate、beta0、相机内参和延迟均为示例假设。

```powershell
.\.venv\Scripts\python.exe demo_step4.py
.\.venv\Scripts\python.exe demo_step4.py --camera-mode bearing --output output/step4_bearing
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_fusion*.py' -v
```

默认12秒受控合成实验：雷达10Hz、相机12.5Hz、预测100Hz，含杂波、雷达/相机独立缺帧、低置信度、相机40–160ms和雷达0–80ms迟到。初始两帧沿用第2步明确设定的低噪声fixture。输出`metrics.json`、`timeline.csv`、`update_trace.json`、`replay.png`；逐tick状态和完整6×6协方差与按采集时间处理的参考比较，要求差异不超过1e-12。

注意：`timeline.csv`是收到所有观测后**修正的历史**，不等于系统当时对外发布的实时轨迹。当前没有网络时钟同步、ROS节点、设备驱动或实测延迟测量。测试包括迟到后重新门控原始点云、原始相机框重新线性化、独立100Hz矩阵递推、非网格时间分段Q、重复事件、零强度和相机不能单独初始化。

2026-10-06验证：9项相关测试全部通过；默认实验初始化于0.1秒，1199个预测ticks，153次迟到事件，接受113次雷达/128次相机更新。与采集顺序参考相比，完整状态和协方差的最大绝对差均为0；最小协方差特征值4.2074e-5，对称性误差为0。图已查看。
